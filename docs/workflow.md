# Browser Flow 流程标准

本项目的默认流程是**固定导航说明 + 模型逐步编排 + 底层代码校验**。站点接入和业务路径扩展沿用现有六工具及 `/api` 通道，不要求建立全自动网站业务状态机。

## 三层分工

| 层次 | 固定内容与责任 | 必要性 |
|---|---|---|
| 固定导航说明 | 在忽略目录 `tasks/<definition>/` 保存公开站点数据、操作目标、起点条件、菜单路径、已知分支、页面地标、允许动作、禁止动作、停止条件和成功判据 | 缺少明确说明，模型无法确定业务范围和何时停止；仅凭按钮名称无法判断是否完成 |
| 模型逐步编排 | 读取当前页面，判断所处阶段、菜单是否展开、下一项允许动作及工具参数；根据实际结果决定继续、重新观察或停止 | 登录态、页面阶段和 DOM 会变化，固定点击序列不能证明每一步操作正确 |
| 底层代码校验 | Host／Client 校验授权、Agent／Session／页面绑定、连接代次、租约、epoch、回执身份、sequence 和剩余预算；页面程序校验文档身份、元素引用、歧义及可操作性 | 模型判断不能代替授权和协议检查，旧引用、错误回执或过期命令必须由代码拒绝 |

用户负责人工登录、显式授权，以及具体任务约定的人工作业。模型不得自行授予或恢复控制权；登录失效时交还用户。

固定说明描述已知路径和判定依据，不穷举全部页面状态，也不要求模型机械执行每一项点击。已到达某阶段时，由模型根据新观察执行剩余步骤。

## 每一步如何执行

1. 先在面板创建或打开当前 Session 的任务，通过 `browser_observe(view:"task")` 读取目标、范围和快照说明，再确认授权页面，通过 `browser_tabs` 和 `browser_observe` 获取实际页面与当前引用。
2. 根据说明和页面地标判断阶段。遇到登录跳转、异常对话框、未知阶段或信息不足时停止并报告；不得猜测业务身份或完成状态。
3. 使用 `browser_find` 定位当前步骤允许的目标。只使用当前页面返回的 `documentToken` 和 `elementRef`；匹配歧义时停止，不取第一项或按位置猜测。
4. 使用 `browser_act` 执行一次允许动作。`dispatched: true` 只表示动作已派发，不能证明导航、保存或业务提交成功。
5. 重新观察，并按说明使用 `browser_wait` 或回读结果核验变化。文档替换后重新取得引用；达到全部终点判据立即停止，保留页面，按用户要求释放控制。

出现 `unknown_outcome`、超时或连接失效时，先停止写操作，只读核对。不能确认结果时报告实际状态，不自动重做点击。代码不自动重发已交付命令；该任务出现未知写后，代码拒绝全部后续 `browser_act` 和新文件授权；新 run、范围修订及重启均不能解除，只允许安全读取、撤销和交接。

## 代码校验的范围

授权、连接和命令生命周期继续由代码维护状态。这些机制负责确定谁能操作哪个页面、命令是否仍有效及结果归属，与网站业务步骤的编排分工不同。具体已实现的检查见 [协议与安全属性](../README.md#protocol-and-safety-properties)。

普通任务由模型逐步遵守与核对说明；通用适配器不按全部网站的业务含义拦截。受信任适配器可以强制限制所支持的业务动作及停止位置；具体保证由实现和对应反例确定，不能推及其他网站，也不能把动作范围校验当作下一步业务编排。

若任务确实需要新增代码强制的业务限制，先说明可复现的失败和所需保证，再在现有操作入口加入最小校验及对应反例。单项校验不要求扩建整站状态机。

## 站点接入与交付

本地导航说明与公开定位数据放在忽略目录 `tasks/<definition>/`，不随插件包交付；受信任安全规则及五模块代码正常提交和打包。不复制登录凭据、存储状态、私有人员数据或原项目运行环境。已有技能入口仅提示读取当前任务；当前任务快照通过正常工具结果入录，也可从普通提示词开始。技能入口沿用各站点的调用权限，技能发现服务缺失不阻断六工具使用，也不是导航能力的额外验收条件。

优先级按实际失败确定：授权失效、跨身份操作、错误派发和回执污染先修；阻断已约定路径的定位或交互缺陷随后处理。每项任务记录必要性和最小完成判据。截图、复杂表格、通用引擎、生成器及辅助工具优化仅在任务明确需要时纳入，不阻塞独立可交付的路径。

产品缺陷先用现有设施补充失败反例，再修复并验证受影响路径；产品变更需同步 Client bundle 和 Host／Client 重载。本地检查与正常 Agent 在所用 Desktop 上的真实页面验证分别记录，并绑定实际候选；纯文档变更复用未变产品已有检查，不为文档改动重复构建或重启。

## 公开内容与私有任务

公开文档只说明通用能力、接口和限制。具体站点操作说明、个人待办、批次、文件、登录状态、机器路径、运行身份和验收原件保存在本地忽略目录，不进入公开仓库或安装包。合成夹具和受信任校验代码可以提交，但不得夹带真实运行数据。

发布审查检查全部待发布文件和可达历史，包括文档、脚本默认值及归档内容；不能仅凭 `/tasks/` 被忽略就声明符合要求。历史原件在本地完整保留，修正公开内容不修改原件。
