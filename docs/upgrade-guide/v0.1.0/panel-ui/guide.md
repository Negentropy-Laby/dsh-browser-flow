# Browser Flow panel layout

Reload the matching Host and Client after rebuilding. The Client now requires
the target Host’s shared `Button`, `Input`, `Tag`, `StateDot` and `DisclosureRow`
exports. A missing control reports a compatibility error. The Client factory
installs the bundled, root-scoped stylesheet once per plugin; unloading the
plugin removes it. Opening another panel does not install another stylesheet.

The panel uses a compact single column. Connection, authorization status and
revocation stay above the content scrollport. A bound task defaults to its goal
and localized lifecycle; edit, cancellation and handoff are explicit controls.
Editing starts from the full Host goal and allowed origins. Polls preserve the
draft; a changed RunScope requires an explicit reload. Cancelling a draft does
not revoke control or send a revision.

Waiting, read-only history and unknown-write restrictions stay in the content
status area. Unknown lifecycle values disable dependent operations. Permission
withdrawal remains available while forms or derived graphs are busy. Technical
identities and raw error codes are in expandable details. Page cards retain
selectable full addresses and identities. File preparation is visible only for
a supported, unblocked import workflow with a current page grant; its full path,
kind, row count, size, SHA-256 and stop condition remain visible before confirmation.

Browser Flow v3, Desktop bridge v1, journal v1, the six tools and seven routes
are unchanged. The task summary now retains the complete bounded goal, avoiding
truncation when initializing an edit. No existing journal or evidence is rewritten.
Waiting tasks retain explicit page authorization and file preparation so users
can supply requested capabilities. Resuming a wait grants no control.
These UI states do not establish login, manual authorization or business success.
